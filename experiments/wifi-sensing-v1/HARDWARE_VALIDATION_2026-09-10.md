# Wi-Fi sensing hardware validation — 2026-09-10

This note records the first physical validation of the standalone Wi-Fi sensing experiment on the real Newo and Newo2 hardware. It intentionally records measured facts, not feasibility claims about gesture recognition, sleep staging, respiration, identity, or health signals.

## Hardware and topology

- Newo: ESP32-S3, 16 MB flash, 8 MB PSRAM.
- Newo2: GOOUUU ESP32-S3-CAM, ESP32-S3, 16 MB flash, 8 MB PSRAM.
- Both stations associated to the same fixed 2.4 GHz access point on channel 3.
- Host collector received NCSI records over UDP/5005.
- Newo and Newo2 production flash layouts were backed up before experiment flashing.
- Experiment images were flashed app-only at `0x10000`; production bootloaders and partition tables were not replaced.
- Secure boot and flash encryption were disabled on both tested boards.

Local secret-bearing `sdkconfig` files, Wi-Fi credentials, raw captures, binaries, and device backups remain outside Git.

## Router-to-Newo gate validation

A temporary local hardware-validation build bypassed the cadence gate for AP-originated CSI while leaving the ESP-NOW peer path gated. This was used to determine whether the previous retained rate was limited by the radio or by the software minimum-spacing gate.

A 120 s mostly-static occupied-room capture produced:

| Metric | Router → Newo |
| --- | ---: |
| CSI frames | 2,929 |
| retained rate | 24.406 Hz |
| callback delta | 3,125 |
| accepted delta | 2,934 |
| source-filter drops | 191 |
| intentional gate drops | 0 |
| ring drops | 0 |
| device UDP drops | 32 |
| mean RSSI | -61.468 dBm |

This established that the AP path naturally supplied roughly 24–26 qualifying observations/s in that setup and that the earlier ~17 Hz retained rate was caused by the minimum-spacing gate, not by an ESP32-S3 processing limit.

The AP-gate bypass was a local physical-validation edit and is not implied to be the final production policy.

## Two receiver AP validation

With both Newo and Newo2 fixed in different room positions and both generating 20 Hz gateway traffic, two 300 s busy-room runs were recorded with two people walking/talking normally.

### Run A

| Metric | Router → Newo | Router → Newo2 |
| --- | ---: | ---: |
| CSI frames | 13,370 | 13,403 |
| packet rate | 44.566 Hz | 44.678 Hz |
| mean RSSI | -63.875 dBm | -51.721 dBm |
| device UDP drops | 118 | 33 |
| ring drops | 0 | 0 |
| intentional gate drops | 0 | 0 |

### Run B

| Metric | Router → Newo | Router → Newo2 |
| --- | ---: | ---: |
| CSI frames | 13,619 | 13,033 |
| packet rate | 45.398 Hz | 43.447 Hz |
| mean RSSI | -61.478 dBm | -51.180 dBm |
| device UDP drops | 79 | 244 |
| ring drops | 0 | 0 |
| intentional gate drops | 0 | 0 |

The total CSI count differed by only 121 frames between the two five-minute runs (26,773 vs 26,652), showing good capture repeatability under uncontrolled room motion. Newo2 had elevated UDP loss in Run B; this was transport loss, not ring overflow.

The higher ~44–45 Hz AP-path rate relative to the single-node ~24 Hz baseline is expected from the additional controlled gateway traffic generated by the second station. Packet rate itself must therefore not be used as a movement feature.

## CSI geometry observed

The dominant AP CSI geometry was 612 bytes, with 376-byte frames as a smaller class and occasional 128/256-byte frames. During the second busy-room run, 256-byte frames appeared on both receivers at the same time.

For later DSP, CSI geometries must be partitioned by receiver/path and PHY/LTF metadata rather than mixed blindly. Stable subcarrier indexing and phase processing require a stable geometry class.

## ESP-NOW third-path validation

ESP-NOW was then enabled with:

- Newo: receive role.
- Newo2: transmit role.
- configured application probe cadence: 20 Hz.
- both stations still associated to the same AP/channel.

A 60 s three-path validation produced all three expected paths:

- `ROUTER_NEWO`
- `ROUTER_NEWO2`
- `NEWO2_NEWO`

### Probe delivery

Newo2 diagnostics:

- transmit attempted: 1,079
- queued: 1,079
- link success: 1,079
- link failure: 0
- submit failure: 0
- skipped busy: 131
- skipped unassociated: 0

Newo diagnostics:

- valid probes received: 1,079
- invalid probes received: 0

Every queued/link-successful application probe in this 60 s run matched a valid receive on Newo. The scheduler attempted approximately 20 operations/s, but 131 slots were skipped because one ESP-NOW send was still in flight, yielding about 18 successful application probes/s.

### CSI paths during the same run

| Path | CSI frames | rate | mean RSSI |
| --- | ---: | ---: | ---: |
| Router → Newo | 3,199 | 53.370 Hz | -63.520 dBm |
| Router → Newo2 | 2,473 | 41.232 Hz | -68.961 dBm |
| Newo2 → Newo | 1,855 | 30.900 Hz | -52.950 dBm |

The peer path also reported 5,552 intentional path-gate drops on Newo during the 60 s session, while ring drops remained zero.

A key result is that `NEWO2_NEWO` CSI records are **not one-to-one with application probe packets**. The receive-side CSI callback observed substantially more peer-originated RF events than the 1,079 validated application probes. The exact lower-level frame composition should be classified before treating peer CSI count as probe count. Application-level probe counters remain the authoritative probe-delivery metric.

## What is now established

- Both ESP32-S3 boards can collect CSI simultaneously on the same fixed AP channel.
- Two fixed spatial receiver positions produce stable independent AP paths.
- The callback/ring design sustained the tested load with zero ring overflow.
- AP-path minimum-spacing gating can discard useful irregularly timed CSI observations.
- Two stations generating gateway traffic can raise usable AP CSI cadence into the mid-40 Hz range in this room.
- Newo2 → Newo ESP-NOW probes work while both stations remain associated to the AP.
- Application-level ESP-NOW delivery was lossless for queued probes in the 60 s validation.
- Peer-originated CSI callback count must not be equated with application-probe count.
- UDP transport loss exists and must remain visible in sequence/status diagnostics.

## Gesture-trigger direction

The target application is a learned gesture trigger for Newo, not a generic packet-rate detector.

The next extraction work should:

1. keep each path and CSI geometry separate;
2. derive amplitude and phase from raw I/Q;
3. use short time windows and measure motion-sensitive changes such as amplitude variance, phase change, short-time energy, and cross-path agreement;
4. first prove separation of stillness, walking, and one deliberately repeated gesture;
5. keep busy-room and overnight resting captures as negative/background data so gestures do not fire on ordinary movement;
6. only add more gesture classes after held-out repetitions are reliably separated.

Packet count, packet cadence, and mean RSSI alone are not sufficient gesture features.

## Overnight background capture

The first long background run is planned with two people sleeping/resting naturally in the room, Newo fixed and USB-connected to the collector PC, and Newo2 fixed separately and powered from a power bank.

The dataset should be labeled as overnight resting/sleep background, not as validated sleep-stage data. It can support later analysis of still periods, turns, larger movements, and false-trigger rejection. With two people present, the RF signal is a mixture and must not be assumed to identify which person produced a movement.

Newo serial logging can run in parallel with the host collector; Newo2 diagnostics remain available through NCSI status/diagnostic records even when its serial port is unavailable.
